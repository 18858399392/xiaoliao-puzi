# Starter Content and Review Implementation Plan

**Goal:** 删除清空喜欢及浏览计数；四分类首屏使用项目自带、可筛选的真实内容，并解释上游数量与随机机制。

**Architecture:** `starter-content.js` 是小型已选内容包，页面同步装载后立即渲染。`content-buffer.js` 管理分类缓存、历史去重及有限并发的后台补充。`content-review.html` 从候选库筛选，可导出 JSON，在本地服务中保存并更新内容包；服务器只接受已知候选 ID。

**Tech stack:** 现有 HTML/CSS/JavaScript、Python 本地服务器、Playwright 验证。

## Tasks

- [x] 删除清空喜欢按钮、相关回调和已看数量 UI；保留内部历史作为去重依据。
- [x] 收集当前上游三个文字 JSON，按文本去重并保持 API 的原始首个 index；采集音乐入口的当前片段并缓存短音频，保留来源与 MIT notice。
- [x] 生成每类默认 60 条文字、8 个音频的初始包；候选库提供全部文字及已验证本地音频供筛选。
- [x] 实现同步缓存取出、完整浏览器历史、有限并发/超时/镜像冷却/部分成功；有本地数据时不等待 API。旧分类结果只进入其缓存。
- [x] 首屏字体 CSS 改为非阻塞加载，保留字号/主题/点赞效果。
- [x] 构建可搜索、分页、试听、逐项剔除、恢复、选择及导出/本地保存的简单筛选页。保存只更新已选内容包，不修改原喜欢或浏览记录；显式剔除 ID 也过滤后台结果。
- [x] 在 Python 本地服务增加受约束的保存端点、原子写入和备份；公开静态部署没有此写端点时可导出选择包。
- [x] 验证首次无缓存且 API 慢/失败时四类即时出内容；缓存滚动补充、跨刷新去重、快速分类切换、音频本地播放、筛选导出/应用及旧喜欢保留。
- [x] 输出最新项目包、独立筛选 HTML、数据审计和解释；保存本地提交，继续只做本地预览。

策略：随机请求本身可能抽重复，页面按 ID 过滤历史。只在当前浏览器记录范围内去重，不声称服务器识别用户或跨设备永久不重复。记录不自动重置；没有新内容时保留说明和重试入口。
